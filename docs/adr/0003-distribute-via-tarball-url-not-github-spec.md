# Distribute via a GitHub tarball URL, not the `github:` npm spec

A real user's `run.bat` run failed with `ENOENT spawn git`: npm's `github:owner/repo` shorthand resolves by shelling out to a locally installed `git`, which this user's machine didn't have — a dependency the project never checked for or documented, on top of Node.js.

Investigating that error surfaced a second, more severe problem underneath it: the repository had been **private** since creation, despite `gh repo create --public` being used and every doc since assuming it was public. Every one of this session's own successful `npx github:...` tests had been silently authenticated as a side effect of `gh auth setup-git` having configured a git credential helper for the developer's own account — so they never exercised the path a real stranger without repo access would actually hit. Fixed by making the repo public (a human-approved action, not one this agent could take on its own).

With the repo now genuinely public, the `github:` shorthand still requires Git specifically. Switched the documented and `run.bat` install command to `npx https://github.com/Babyferret/chatdiwa/archive/refs/heads/master.tar.gz` instead: npm/npx install tarball URLs via plain HTTPS + extraction, with no Git involved at all, verified end-to-end (`npm install` from a downloaded copy, and `npx` against the live URL natively via cmd.exe). The URL always reflects the current tip of `master` — same "always latest, no separate update step" property as the `github:` spec — so this is a pure dependency reduction, not a behavior change.
